# Excel → Markdown 변환기

`excel_to_markdown.py`는 Excel 파일(`.xlsx`, `.xls`)을 읽어 모든 시트의 내용을
**GitHub Flavored Markdown 표** 형식으로 저장하는 파이썬 스크립트다.

## 사용법

```bash
# 의존성 설치
pip install pandas openpyxl

# 모든 시트를 input.md 로 변환
python excel_to_markdown.py input.xlsx

# 출력 파일 지정
python excel_to_markdown.py input.xlsx -o result.md

# 특정 시트만 변환
python excel_to_markdown.py input.xlsx --sheet Sheet1
```

출력 파일에는 시트 이름이 `## 시트: 이름` 헤더로 들어가고, 그 아래에 표가 만들어진다.
셀에 포함된 `|` 문자는 `\|` 로 이스케이프되고, 줄바꿈은 `<br>` 로 치환되어 표가
깨지지 않는다.

## 마크다운(Markdown)이란?

마크다운은 2004년 John Gruber가 만든 **경량 마크업 언어**다. 일반 텍스트에 몇 가지
간단한 기호(`#`, `*`, `-`, `|` 등)를 덧붙여 문서 구조(제목, 목록, 표, 코드 블록,
링크 등)를 표현한다. 원본 자체가 사람이 읽기 쉬운 평문이며, 변환기를 거치면 HTML,
PDF, 슬라이드 등으로 렌더링된다. GitHub README, 기술 블로그, 위키, 노션, 옵시디언
같은 도구에서 사실상 표준 포맷으로 자리잡았다.

대표적인 문법은 다음과 같다.

| 문법 | 의미 |
| --- | --- |
| `# 제목` | 1단계 헤더 (h1) |
| `**굵게**` | 볼드 |
| `*기울임*` | 이탤릭 |
| `- 항목` | 순서 없는 목록 |
| `` `code` `` | 인라인 코드 |
| `[텍스트](url)` | 링크 |
| `\| a \| b \|` | 표(GFM 확장) |

## 마크다운 vs 엑셀: 차이점

| 구분 | 마크다운 (.md) | 엑셀 (.xlsx) |
| --- | --- | --- |
| 파일 형식 | 일반 텍스트 (UTF-8) | 압축된 XML(OOXML) 바이너리 |
| 핵심 용도 | 문서 작성, 가독성 있는 기록 | 표 계산, 데이터 가공·분석 |
| 수식·함수 | 없음 (정적 표만) | `SUM`, `VLOOKUP` 등 풍부한 함수 |
| 셀 서식 | 없음 (스타일 불가) | 색·폰트·테두리·조건부 서식 |
| 차트/피벗 | 미지원 (이미지 첨부만) | 기본 지원 |
| 편집 도구 | 어떤 텍스트 에디터든 가능 | Excel, LibreOffice, 구글시트 등 전용 앱 |
| Git diff/병합 | 줄 단위로 깔끔하게 비교 가능 | 바이너리라 diff/병합 어려움 |
| 자동화·파싱 | grep/sed/스크립트로 쉽게 처리 | 라이브러리(`openpyxl` 등) 필요 |
| 렌더링 | GitHub, 위키, 블로그 등 어디서나 | Excel 또는 호환 뷰어 필요 |
| 대용량 데이터 | 수천 행 넘어가면 가독성 저하 | 수십만 행까지 무리 없이 처리 |

## 장단점 정리

### 마크다운의 장점
- **가볍고 이식성이 높다** — 어떤 OS·에디터에서도 그대로 열린다.
- **버전 관리 친화적** — Git에서 줄 단위 diff/리뷰/머지가 가능하다.
- **렌더링 호환성** — GitHub, GitLab, Notion 등 거의 모든 도구가 지원한다.
- **자동화 용이** — 텍스트라서 스크립트로 생성·가공·검색이 쉽다.

### 마크다운의 단점
- **계산 기능 없음** — 수식이나 동적 집계가 불가능하다.
- **표 편집 불편** — 열이 많아지면 손으로 정렬하기 어렵다.
- **서식 표현 제한** — 셀 색상, 병합 셀, 차트 등을 표현할 수 없다.
- **대규모 데이터에 부적합** — 수천 행을 넘어가면 가독성이 급격히 떨어진다.

### 엑셀의 장점
- **강력한 데이터 처리** — 수식, 피벗, 차트, 매크로(VBA)까지 지원한다.
- **풍부한 시각화** — 조건부 서식, 그래프로 데이터를 한눈에 보여준다.
- **대용량 표 처리** — 수십만 행도 빠르게 다룰 수 있다.
- **업무용 표준** — 회계·재무·통계 분야의 사실상 표준 포맷이다.

### 엑셀의 단점
- **버전 관리 불리** — 바이너리 파일이라 diff/머지가 사실상 불가능하다.
- **유료/전용 소프트웨어 의존** — Excel 라이선스가 필요하거나 호환 도구를 써야 한다.
- **이식성 낮음** — 웹·문서·코드 리뷰 흐름에 그대로 끼워 넣기 어렵다.
- **자동화 비용** — 프로그램으로 다루려면 라이브러리와 추가 처리가 필요하다.

## 언제 어느 것을 쓰면 좋을까?

- 코드 리포지토리의 **문서·릴리스 노트·간단한 비교표**라면 → 마크다운
- **수식 계산·대용량 데이터 분석·차트가 필요한 업무**라면 → 엑셀
- 엑셀로 작성된 결과를 **PR/리포트에 그대로 첨부하고 싶을 때** → 본 스크립트로
  마크다운 변환 후 첨부
